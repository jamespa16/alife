# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

An artificial-life sandbox: creatures with evolving recurrent neural-net brains eat, move, split and die on a toroidal food grid. There is no fitness function; selection comes only from survival and reproduction. Everything runs as batched PyTorch tensor ops on the GPU (CUDA, then Apple MPS, then CPU, chosen in `config.py`), and pygame displays it.

## Commands

```sh
uv sync                # install deps, incl. dev group (ruff, ty)
uv run alife           # run the sim (entry point: alife.app:main)
python -m alife        # same thing, without uv
uv run alife --headless --steps 20000 --seed 1 --log run.csv --set THINK_COST=0
                       # experiment run: no window, seeded, CSV every --log-every (100) steps
uv run alife --headless --steps 3000 --seed 1 --species-log species.csv   # species births/extinctions
uv run alife --headless --steps 5000 --save w.alife   # then: --load w.alife --steps 10000 --set THINK_COST=0.004
                       # fork a run; --steps is the absolute t, --save-every N also saves along the way
uv run ruff check      # lint (--fix to autofix)
uv run ruff format     # format
uv run ty check        # type-check
uv run pytest          # all tests (~10s; runs on the GPU device like the sim)
uv run pytest tests/test_brain.py::test_empty_batch   # a single test
```

There's no CI.

Testing notes:
- `tests/test_brain.py` checks `think()` against a per-creature reference built from the genome layout.
- `tests/test_cli.py` runs `python -m alife` in a subprocess, because `--set` must run before the sim modules are imported, and pytest has already imported them.
- Worlds share torch's global RNG. To compare two seeded worlds, run them one after the other, not interleaved.

Runtime keys: H toggles the HUD (population, mean loops, diet, loop histogram; sampled from `census()` every 0.5 s), S saves a snapshot to `alife-<timestamp>.alife`, SPACE pauses, C cycles the colour mode (lineage / loop count / diet / species), and UP/DOWN doubles or halves the sim steps per frame (1–64), M drops a meteor at the mouse (`World.meteor`), F floods the map with food (`World.flood`), P starts a plague (`World.plague`). Inspector: left click selects the nearest creature (within `PICK_RADIUS` px) and opens a side panel (genome heatmaps by brain block, live hidden state `h`, loops, age, energy, uid/gen/species, diet/body/pick genes; shows DEAD and keeps the last data once it dies). Mouse wheel zooms at the cursor (1 to `ZOOM_MAX`), right-drag or Shift+arrows pan, V toggles a camera that follows the selection, 0 resets the view, Escape deselects. M drops its meteor at the world point under the mouse. The window is resizable: the view scales to fit, keeping the world's aspect ratio with black bars (`View.resize`/`View.dest`); the HUD is rebuilt at the view scale (`make_hud(scale)`, at least 0.75) and the inspector panel stays at fixed pixel size. The window title shows t, population, mean loop count and steps/s. The world resets automatically when the population hits zero.

Each CSV row comes from `World.census()`: `t`, `pop`, means of loops/energy/age/food, and `loops_1..loops_K_MAX` histogram counts, plus `mean_diet`, `carnivores` (diet > 0.5) and `meat` (total) when `PREDATION` is on, `mean_pick` when `SEX` is on, and `n_species` when `SPECIES` is on. `--species-log PATH` writes species events to a CSV with columns `t,event,species,parent_species,size` (`event` is `new` or `extinct`; extinct rows have an empty parent and the species' size at the previous pass). The same seed gives an identical CSV on the same device. `--set NAME=VALUE` overrides any int/float constant in `config.py`, except the derived ones (`N_IN`, `G`, `TAU`). In windowed mode, extinction resets the world, so `t` restarts in the log.

## Architecture

**Save files.** `World.save(path)` / `World.load(path)` store every tensor, bool, int and float in `vars(s)` (except `World.TRANSIENT`, i.e. the render `trail`), the config snapshot, and the torch CPU and device (CUDA/MPS) RNG states, so a loaded run continues bit-identically on the same device. It is generic: a new tensor attribute is saved automatically, but a new non-numeric attribute (list, dict) is not, so keep state in tensors or numbers, and add render-only state to `TRANSIENT`. `load` raises if the shape constants (`config.SHAPE_KEYS`) differ and warns on any other changed constant, so `--load` plus `--set` forks a run under new rules. `*.alife` is gitignored.

**Constants are copied at import.** `world`, `brain` and `render` use `from .config import X`, so `config.override()` must run before they're imported. It raises if they already have been. That's why `app.main()` imports `World`, `render` and pygame inside the function. Keep `app.py` and `__init__.py` free of top-level imports of the sim modules.

Module flow: `app` (CLI, logging, headless and pygame loops) → `world.World.step()` → `brain.think()`, with `render` turning a `World` into a frame and `hud.draw_hud` drawing census history graphs (pure function of the history list; pygame is imported inside `main()` like `render`). All tunable constants live in `config.py`.

**Fixed-size structure-of-arrays state.** Each per-creature attribute (`pos`, `heading`, `energy`, `age`, `genome`, `loops`, `h`, `color`, `diet`, `pick`) is a tensor of length `N_MAX`, and the `alive` bool mask marks which slots are in use. Dead slots still go through every computation; their effects are masked out with `alive_f`. Birth means writing into free (`~alive`) slots, and death just clears `alive`. To add a new per-creature attribute, you must:
1. allocate it in `World.reset()`
2. copy or mutate it from parent to child in `World.reproduce()`

**Genome ↔ brain layout coupling.** The genome is a flat vector of length `G`, defined in `config.py`. `brain.think()` slices it, in order, into `w_in [N_HID×N_IN]`, `w_rec [N_HID×N_HID]`, `bias [N_HID]` and `w_out [N_OUT×N_HID]`. If you change the brain shape, `G` and those slices must stay consistent. `N_IN` and `N_OUT` are derived in `config._derive()` (so `--set PHERO_CH=n` or `PREDATION=0` re-derives them and `G`) and must match the sensor columns built in `World.step()` (food×3, density×3, own energy, then 3 per pheromone channel, then meat×3 and nearby aggression×3 if `PREDATION`, then wall×3 and poison×3 if `TERRAIN`) and how it reads the outputs (turn, speed, then one deposit per pheromone channel, then attack if `PREDATION`). To add sensors or outputs, append columns in `step()` and extend `_derive()`.

**Loop count is a gene.** `loops[i]` (1..`K_MAX`) sets how many recurrent passes creature i's brain gets. Each pass costs `THINK_COST` energy, and the value mutates by ±1 with probability `LOOP_MUT_P`. For batching, `think()` runs up to the largest loop count present and uses `torch.where` to freeze `h` once each creature has used up its loops.

**Performance.** `think()` dominates step time; the batched `bmm` over tiny per-creature matrices is the cost. `World.step()` therefore runs the brain only on living creatures, gathered by index, and dead slots get zero output. Elementwise multiply-sum was tried instead of `bmm`: it's 2× slower on MPS. Each step has a few unavoidable GPU syncs (`nonzero`, `loops.max()`), so don't add more in the hot path. To profile, time sections with `torch.mps.synchronize()` (or the CUDA equivalent) around them. Without the sync, GPU time shows up in whichever op syncs next.

**Brains have memory across steps.** Each creature's hidden state `World.h [N_MAX, N_HID]` persists: `think(genome, loops, x, h)` starts from the previous step's `h` and returns `(out, new_h)`. Newborns start with `h = 0`.

**Family and species.** Every creature has `uid` (unique, from the device counter `next_uid`, so no host sync; founders are 0..N_INIT-1), `parent_id` (first parent, -1 for founders), `gen` (generation depth, max of the parents + 1) and `species`. `World.birth_ids(kids, a, b)` sets them in both `reproduce()` and `reproduce_sex()`; newborns inherit the first parent's species. With `SPECIES=1`, `update_species()` runs in `reset()` and every `SPECIES_EVERY` steps (it syncs, which is fine that rarely): living genomes within `SPECIES_DIST` (RMS per gene) of a known species' mean genome (`sp_ids`, `sp_rep`, `sp_size`) keep that id; the rest form new species by greedy leader clustering, at most `SPECIES_NEW_MAX` per pass (stragglers join the nearest). A new species' `parent_species` is the most common previous species among its members. Empty species go extinct. Events accumulate in `World.events`; `take_events()` drains them and `app.SpeciesLog` writes them to CSV. It draws no RNG, so `SPECIES=0` reproduces the pre-species run and CSV exactly. All of these are plain tensors, so `save` and `load` cover them. In a recombining population (`SEX=1`) genomes are a well-mixed pool and are nearly equidistant, so species structure is weak; it is much clearer with `SEX=0`.

**Inspector code.** `panel.py` holds `View` (zoom/pan maths), `pick_nearest`, `fetch` (two small host copies for the selected slot, once per frame), `Inspector` (selection state, marks dead when the uid at the slot changes) and `draw_panel` (pure, tested with `SDL_VIDEODRIVER=dummy`). `run_window` renders the full frame, then crops and scales it with `pygame.transform` for zoom.

**Step order** (`World.step`): bin creatures into grid cells → eat (food split among creatures sharing a cell, capped at `EAT_RATE`; with `PREDATION` plants feed by `1 - diet` and the `meat` grid by `diet`, capped at `MEAT_EAT_RATE`) → sense (box-blurred food and density, sampled at `SENSE_ANGLES` and `SENSE_DIST` ahead) → think → move → predation (attack = `sigmoid(out - ATTACK_BIAS)`; each creature loses `ATTACK_RATE` × the attack of the others in its cell, capped at its energy, and attackers share the loss in proportion to attack, scaled by their `diet`; attacking costs `ATTACK_COST`) → pheromone deposit → metabolism, ageing and death (the dead drop `MEAT_DROP` of their energy onto `meat`) → reproduce (with `SEX=0`: energy > `REPRO_E` splits the creature in half; the child gets a mutated genome, loop count and lineage colour; with `SEX=1`, see below) → `t` advances and `fert` is recomputed (`update_fert`: the base map `fert0` slid sideways by `FERT_DRIFT` cells/step, scaled by `1 + SEASON_AMP*sin(TAU*t/SEASON_PERIOD)`; a function of `t` only) → food regrows toward `fert`. The pheromone grid `World.phero` `[PHERO_CH, H, W]` then diffuses (`blur`, `PHERO_DIFFUSE`) and decays (`PHERO_DECAY`); sensors read it through `tanh`, and `PHERO_CH=0` disables it. Deposits are quantised to 1/1024 and summed into an empty grid before being added, so the unordered `scatter_add_` stays reproducible per seed. Predation state: `World.meat` `[H, W]` (carrion, ×`MEAT_DECAY` per step), `World.aggr` (last step's summed attack per cell; blurred, it is the aggression sensor), per-creature `diet` (0 herbivore .. 1 carnivore, mutates by `DIET_MUT_STD`, starts at `rand ** DIET_INIT`). `PREDATION=0` disables all of it and reproduces the pre-predation run exactly. Eaten and stolen amounts are quantised to 1/1024 and summed into empty grids, like pheromone deposits. Render colour mode 2 shows diet (C cycles lineage / loops / diet). Plague runs at the start of the step while `plague_left > 0` (per-creature `sick` mask: spreads within a cell, drains `PLAGUE_DRAIN` energy). Newborns are healthy. Sexual reproduction (`SEX=1`, default; `SEX=0` reproduces the pre-sex run exactly, including the CSV columns): `reproduce_sex` pairs eligible creatures (energy > `REPRO_E`; both partners must be eligible) in `pair_up`: shuffle with `randperm`, stable-sort by grid cell, pair 1st+2nd, 3rd+4th... of each cell's run, and keep a pair only if the colour distance is below both partners' `pick` (the mate-preference gene, starts at `rand * PICK_INIT`, mutates by `PICK_MUT_STD`). Pairs are taken in random order up to the free slots. Padding pairs are masked (`ok`), not compacted, so no extra host sync; any new in-place write to parents in `reproduce_sex` must tolerate padding pairs repeating a real parent's slot (use `index_add_` of zeros). Each parent pays `SEX_COST` of its energy, the child gets both payments. The child's genome is a per-gene uniform crossover plus `MUT_STD` noise; loops come from one parent (+-1 mutation); diet, pick and colour are the parents' mean plus noise. Only one cell-run alignment is tried per step, so a cell with a mismatched neighbour wastes a chance; it retries next step. Terrain (`TERRAIN=1`, default; `TERRAIN=0` reproduces the run exactly): `make_terrain()` in `reset()` builds `World.wall` and `World.poison` (`[H, W]` bool) from bicubic-upsampled noise (`TERRAIN_SCALE` cells across), thresholded by quantile to cover `WALL_FRAC` and `POISON_FRAC` of the map. Blobs, so most of the map stays open. It draws RNG only when on, and a new map is made on every reset. Walls zero `fert` (via `World.open`), so no food grows there. A creature whose move would land in a wall slides along x or y if that is open, else stays. Poison drains `POISON_DRAIN` energy per step at the creature's new cell. Two sensor groups (wall, poison; `s.terr_s`, precomputed once and blurred with radius 2) are read at the `SENSE_ANGLES` points, adding 6 to `N_IN`. Newborns and initial creatures are placed outside walls (`birth_pos`). Meteors and floods leave terrain alone (a flood refills `fert`, which is 0 in walls). Render draws walls grey and poison purple. `render` keeps a fading creature layer in `world.trail` (decay `TRAIL_DECAY` per frame, 0 disables).

**Conventions and gotchas**
- The world wraps in both axes: positions use `% W` / `% H`, and `blur` uses circular padding.
- Grids (`food`, `fert`) are `[H, W]` and indexed `[y, x]`. `render` builds `[H, W, 3]`, then permutes to `[W, H, 3]` because `pygame.surfarray` expects that.
- `World` methods name the instance `s`, not `self`.
- Sim and render code run under `@torch.no_grad()`. Keep tensors on `DEV` and avoid host syncs (`.item()`, `int()`, `.cpu()`) inside `step()`; `stats()` is only called every 0.5s for this reason.
- `reproduce()` is limited by the number of free slots. When the world is full, a random subset of eligible parents (or pairs, with `SEX`) reproduces.
